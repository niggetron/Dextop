# W11C — Web Research Report (Wave 11): data-plane Rust deps, audio, PA protocol, .so hygiene

## Scope inspected
Web-only (websearch/webfetch); no builds, no source edits, no token. Target from BRIEF: Redmi Pad Pro 5G, Android 16 / API 36, HyperOS 3, arm64-v8a, minSdk 33. Aligns with W10C (`rust-toolchain >=1.86`, NDK r28, `ndk::audio`, `rustls`+`rustls-platform-verifier`, UniFFI control / raw-JNI data split — see `.team_waves/W10_WEB.md`). Topics: HTTP/2 range via reqwest/hyper, sha2+ed25519-dalek, zstd/xz parallel decompression, AAudio MMAP Rust crates, PulseAudio native protocol, safe bundled-`.so` removal.

## Findings (P0/P1/P2/P3)

### P1 — HTTP/2 range requests: reqwest is the only realistic Rust client here; it costs tokio
- Range is application-level, not transport: send `Range: bytes=<start>-<end>` (or open-ended `bytes=N-`), require `206 Partial Content` + `Content-Range`, fall back to full GET if server ignores it. `reqwest::header::{RANGE, CONTENT_RANGE, IF_RANGE}` exist; `reqwest-file` implements seek simply by re-issuing a request with `Range` — prove of the pattern. [MDN Range](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Range) · [reqwest header module](https://docs.rs/reqwest/latest/reqwest/header/index.html) · [reqwest-file::RequestFile](https://docs.rs/reqwest-file/latest/reqwest_file/struct.RequestFile.html) · [Rust cookbook partial download](https://rustwiki.org/en/rust-cookbook/web/clients/download.html)
- HTTP/2 is opt-in: `reqwest` needs the `http2` cargo feature; force with `HttpVersionPref::Http2` / `http2_prior_knowledge()` (hyper `Builder::http2_only(true)`). With TLS, h2 must be negotiated by ALPN — reqwest sends ALPN only via rustls; the native-tls/OpenSSL path historically broke `http2_prior_knowledge` (issue #857). [reqwest PR #2162](https://github.com/seanmonstar/reqwest/pull/2162/files) · [hyper client Builder](https://docs.rs/hyper/0.14.9/hyper/client/struct.Builder.html) · [reqwest #857](https://github.com/seanmonstar/reqwest/issues/857)
- Android cross-build: disable `default-tls` (native-tls → OpenSSL = "dragons"); reqwest's own CI builds `--target aarch64-linux-android --no-default-features` with `cargo ndk`. Use `features = ["rustls-tls", "http2", "stream"]` and reuse the W10 rustls-platform-verifier (init from JNI). [reqwest TLS docs](https://docs.rs/reqwest/latest/reqwest/tls/index.html) · [reqwest Android CI fix](https://github.com/seanmonstar/reqwest/commit/adba8672c60923c2cee4f5b62afb8ca666f6d4e9) · [crates.io reqwest](https://crates.io/crates/reqwest/0.12.25)
- **Tension:** reqwest (incl. its `blocking` facade) pulls tokio, which W10C excluded. Options: (a) feature-gate a `downloader` module with `tokio = { features = ["rt-multi-thread","net","time"] }` and keep the control/data plane tokio-free; or (b) if h2 is not actually mandatory for the CDN, use `ureq 3.5` (blocking, pure Rust, no unsafe, small tree, rustls+ring and `platform-verifier` feature) — but ureq 3.x is HTTP/1.1 only (ureq-proto), so it cannot satisfy an HTTP/2 requirement. [ureq docs](https://docs.rs/ureq/3.5.2/ureq/)

### P2 — sha2 / ed25519-dalek: pure Rust, no NDK C toolchain; pin before toolchain
- `ed25519-dalek 3.0.0` (current) is pure Rust on curve25519-dalek 4.x and depends on `sha2` (Sha512 is the Ed25519 hash); crate is edition 2024 → needs rustc ≥1.85 (compatible with W10 pin ≥1.86). API is `SigningKey`/`VerifyingKey` + `Signature` from the `ed25519` crate; use `VerifyingKey::from_bytes()` + `verify()` for signed manifests/WAL. [crates.io deps](https://crates.io/crates/ed25519-dalek/3.0.0/dependencies) · [upstream Cargo.toml](https://raw.githubusercontent.com/dalek-cryptography/curve25519-dalek/main/ed25519-dalek/Cargo.toml) · [diff 2.x→3.0](https://diff.rs/ed25519-dalek/2.2.0/3.0.0)
- `sha2 0.10` for standalone SHA-256 content digests; `default-features = false` keeps it `no_std` if a future bare-metal path appears. No native code, no cross-compile risk. [docs.rs/sha2](https://docs.rs/sha2)
- Caveat: 3.0.0 is a fresh major with API churn; if stability beats features, `ed25519-dalek = "2"` is battle-tested. Decide once, commit `Cargo.lock`.

### P1 — zstd/xz parallel decompression: prefer pure Rust to avoid a second C cross-build
- `zstd` 0.14.x = bindings to C libzstd; the `zstdmt` feature enables multi-threaded **compression** (`n_workers`/`ZSTD_c_nbWorkers`, 0 = off). `zstd-sys` builds C via `cc`, so cargo-ndk must supply NDK clang; reported breakages trace to old clang. [docs.rs/zstd](https://docs.rs/zstd) · [zstd stream Encoder::multithread](https://docs.rs/zstd/latest/zstd/stream/write/struct.Encoder.html) · [cross-compile issue](https://users.rust-lang.org/t/cross-compile-issue-on-zstd/104721)
- Multi-threaded **decompression** is the rarer need: `rusty_zstd` exposes `AdvancedOptions { nb_workers, job_size, overlap_log, .. }` wired to `ZSTD_c_nbWorkers` in `mt.rs` for both directions; libzstd ≥1.4 required. [rusty_zstd AdvancedOptions](https://docs.rs/rusty_zstd/latest/rusty_zstd/struct.AdvancedOptions.html) · [mt.rs source](https://docs.rs/rusty_zstd/latest/src/rusty_zstd/mt.rs.html)
- Pure-Rust alternative with no C toolchain: `zstd-rs` (single-threaded, its `par` module only *plans* jobs and runs them sequentially) — safe default, accept serial decode. [zstd-rs](https://docs.rs/zstd-rs/latest/zstd_rs) · [libzstd-rs-sys](https://github.com/trifectatechfoundation/libzstd-rs-sys)
- xz: `xz2` 0.1.7 is stale; `liblzma` (fork, xz 5.4) adds a `parallel` feature for MT via `lzma-sys` static C (NDK clang needed) [docs.rs/liblzma](https://docs.rs/liblzma) · [crates.io/liblzma](https://crates.io/crates/liblzma). **Best fit:** `lzma-rust2` (pure Rust) with `XzReaderMt<R: Read + Seek>` — real multi-threaded XZ decompressor with no C build; `async-compression` also exposes `xz-parallel` if async is already present. [XzReaderMt](https://docs.rs/lzma-rust2/0.16.5/lzma_rust2/struct.XzReaderMt.html) · [async-compression](https://docs.rs/async-compression/0.4.47/async_compression)
- MT decode needs block-structured frames and RAM (`mem_limit`); for small assets pay no MT cost — choose single-thread crate.

### P1 — AAudio "MMAP" is a stream property, not a separate crate; use `ndk::audio`
- AAudio is a stable public NDK C API since API 26 (MMAP path since 8.1), available on API 33/36. Lowest latency requires `AAUDIO_PERFORMANCE_MODE_LOW_LATENCY` + high-priority callback; `AAudioStream_isMMapUsed()` reports whether the MMAP path (vs legacy) is actually in use — MMAP can be denied by vendor HAL/effects. [NDK AAudio guide](https://developer.android.com/ndk/guides/audio/aaudio/aaudio) · [NDK audio group ref (isMMapUsed)](https://developer.android.com/ndk/reference/group/audio) · [AOSP AAudio/MMAP](https://source.android.com/docs/core/audio/aaudio) · [Oboe low latency](https://developer.android.com/games/sdk/oboe/low-latency-audio)
- Rust options: `ndk = { version = "0.9", features = ["audio"] }` safe `AudioStreamBuilder`/`AudioStream` with `data_callback`, `set_performance_mode(AudioPerformanceMode::LowLatency)` — no C shim [docs.rs ndk::audio](https://docs.rs/ndk/latest/ndk/audio) · [AudioStreamBuilder](https://docs.rs/ndk/latest/ndk/audio/struct.AudioStreamBuilder.html); thin/`unsafe` alternatives `aaudio` 0.1 [crates.io](https://crates.io/crates/aaudio/versions), `aaudio-sys`/`raw-ndk-sys` (bindgen; `AAudioStreamBuilder_setPerformanceMode` available) [raw-ndk-sys](https://docs.rs/raw-ndk-sys/latest/raw_ndk_sys/fn.AAudioStreamBuilder_setPerformanceMode.html); higher-level `cpal` 0.18.2 (AAudio backend, needs `ndk_context::initialize_android_context` from `JNI_OnLoad`) [cpal](https://github.com/RustAudio/cpal); niche `tinyaudio` [crates.io](https://crates.io/crates/tinyaudio), `android_audio` (crosvm) [docs](https://crosvm.dev/doc/android_audio/index.html). None exposes `isMMapUsed` as a safe method — call it via `raw-ndk-sys` only behind a versioned adapter if telemetry needs it.
- Callback rules (already in W10C): no malloc/I/O/mutex/sleep; lock-free ring; buffer ≈2×burst; 48 kHz to avoid SRC; `AudioStream` is not `Send`/`Sync` in ndk 0.9.0. Keep OEM quirks isolated; do **not** add Oboe/C++ unless the Redmi Pad path misbehaves.

### P2 — PulseAudio native protocol: small binary protocol; implement minimally, avoid libpulse C
- Server: `module-native-protocol-tcp` listens on TCP **4713** (default); local clients use Unix socket `/run/user/<uid>/pulse/native`. Auth via cookie (`~/.config/pulse/cookie`) or `auth-anonymous=1`. [freedesktop network doc](https://www.freedesktop.org/wiki/Software/PulseAudio/Documentation/User/Network) · [ArchWiki examples](https://wiki.archlinux.org/title/PulseAudio/Examples)
- Protocol is a length-framed little-endian packet stream with tags/opcodes (`PA_COMMAND_AUTH`, `CREATE_PLAYBACK_STREAM`, `STARTED`/`CORKED`, `GET_SERVER_INFO`); handshake negotiates protocol version and shared memory (SHM can be disabled). Reference implementations: server `protocol-native.c` [source](https://github.com/pulseaudio/pulseaudio/blob/v17.0/src/pulsecore/protocol-native.c), client `pacat.c` [source](https://github.com/pulseaudio/pulseaudio/blob/master/src/utils/pacat.c), trace walkthrough [gavv](https://gavv.net/articles/pulseaudio-under-the-hood) / [protocol diary](https://a-darwish.gitbooks.io/diary-of-pulseaudio-developement/content/protocol_implementation.html). `libpulse-simple` (`pa_simple_new/...`) hides this for C clients [simple.h](https://freedesktop.org/software/pulseaudio/doxygen/simple_8h.html) · [pacat-simple](https://www.freedesktop.org/software/pulseaudio/doxygen/pacat-simple_8c-example.html).
- For Wayland Linux Mode D: implement only AUTH + CREATE_PLAYBACK_STREAM + write loop over `UnixStream`/`TcpStream` (std, no new crate) or, if C is acceptable, `libpulse-sys`. Prefer native protocol to keep the dependency set minimal and the code auditable. Pure-Go reference of the same approach: [christopher-kleine/pulseaudio](https://github.com/christopher-kleine/pulseaudio/blob/289c011d6a333b6e7e9d92c4ab146ce1fa1d2926/client.go).

### P1 — removing bundled `.so` safely: Gradle packaging options + DT_NEEDED audit, not deletion by guesswork
- Remove from `jniLibs` / AAR `jni/` or filter at packaging: `packagingOptions { jniLibs { excludes += listOf("**/libfoo.so") ; pickFirsts += listOf("**/libc++_shared.so") } }`; `abiFilters += "arm64-v8a"` for device builds; per-ABI paths like `lib/x86/*.so` can be excluded wholesale. [AGP Packaging DSL](https://developer.android.com/reference/tools/gradle-api/8.3/null/com/android/build/api/dsl/Packaging) · [JniLibsPackaging](https://developer.android.com/reference/tools/gradle-api/8.11/com/android/build/api/dsl/JniLibsPackaging) · [StackOverflow examples](https://stackoverflow.com/questions/37382057/android-apk-how-to-exclude-a-so-file-from-a-3rd-party-dependency-using-gradle) · [NDK prebuilts guide](https://developer.android.com/ndk/guides/prebuilts)
- Safety sequence: (1) inventory `DT_NEEDED` of every surviving `.so` (`llvm-readelf -d`) — never drop `libc++_shared.so`/`libgcc`/`libunwind` while a linker still needs them; (2) confirm ABI set matches `abiFilters` (no orphan x86 libs); (3) re-check **16 KB `PT_LOAD` alignment** on every remaining `.so` (API 36 / W10 P0); (4) verify APK/ZIP with `zipalign -c -P 16` and a `System.loadLibrary` smoke test on device. [include native symbols/stripping](https://developer.android.com/build/include-native-symbols) · [16 KB page guide](https://developer.android.com/guide/practices/page-sizes)
- For Rust cdylib: do NOT bundle OpenSSL/native-tls `.so` at all — use rustls (already W10C), so the only new native `.so` is `libdextop_core.so` packaged once from cargo-ndk output. Avoid `useLegacyPackaging=true` duplication drift with W10A's jniLibs wiring.

## Deliverable — recommended minimal dependency set (additions to W10C baseline)

| Purpose | Add to `rust-core/Cargo.toml` | Why / caveat |
|---|---|---|
| HTTP/2 range downloads | `reqwest = { version = "0.12", default-features = false, features = ["rustls-tls","http2","stream"] }` + `tokio = { version = "1", features = ["rt-multi-thread","net","time"] }` | Feature-gate into a `downloader` module; reuse W10 rustls + platform verifier; no native-tls. Reqwest CI proves aarch64 build with `--no-default-features`. If h2 is NOT required, swap for `ureq = { version = "3.5", default-features = false, features = ["rustls","platform-verifier"] }` (no tokio, HTTP/1.1 only). |
| Signatures / digests | `ed25519-dalek = { version = "2" or "3", default-features = false, features = ["alloc"] }` + `sha2 = { version = "0.10", default-features = false }` | Pure Rust, Android-safe. Pin major; commit lockfile. 3.x needs rustc ≥1.85 (ok). |
| zstd decode | `zstd-rs` (pure Rust, serial) OR `rusty_zstd` with `nb_workers` if MT decode is measured necessary | Avoid `zstd`/`zstd-sys` C cross-build; `zstdmt` is mainly MT *compression*. |
| xz decode | `lzma-rust2` (`XzReaderMt`, pure Rust MT) | Avoid `liblzma`/`xz2` C toolchain on Android. |
| AAudio | `ndk = { version = "0.9", features = ["audio"] }` (already W10C); add `raw-ndk-sys` only for `AAudioStream_isMMapUsed` | MMAP is a stream property; no separate MMAP crate. |
| PulseAudio | none — std `UnixStream`/`TcpStream` native-protocol subset (or `libpulse-sys` only if Mode D proves complex) | Minimal tree. |
| .so packaging | none — Gradle `packagingOptions.jniLibs` filters + `abiFilters arm64-v8a` | Audit `DT_NEEDED` + 16 KB alignment before/after removal. |

Deliberately excluded: `native-tls`/OpenSSL, `cpal`/Oboe (unless device tests fail), `libpulse`/`libpulse-simple`, `xz2`/`liblzma` C builds, `zstd-sys` unless MT decode is proven needed, `reqwest-file` (Range logic is ~5 lines).

## Risks / device testing needed
1. HTTP/2 on HyperOS mobile networks / captive portals: verify ALPN h2 actually negotiated (`dotnet`-style sniff or server logs) and that 206 + `Content-Range` is honored; confirm resume-after-disconnect with `If-Range`.
2. tokio addition reopens W10C's "no tokio" decision — benchmark binary size/start-up on device; if h2 unneeded, use ureq to keep tree small.
3. ed25519-dalek 3.0.0 API churn — lock version and run host `cargo test` before M5 sign-off.
4. MT zstd/xz: confirm pure-Rust decoders handle the exact update artifacts (frame/block layout, mem limit) and benchmark on the tablet's big.LITTLE cores; MT may not help small files.
5. AAudio `isMMapUsed` on HyperOS 3: MMAP may be disabled by vendor/effects — verify `LOW_LATENCY` callback glitch-free at 120 Hz load and keep SHARED/legacy fallback behind versioned adapter.
6. PulseAudio native protocol: SHM negotiation and cookie auth on the Linux Mode D target; test without SHM first.
7. `.so` removal: on-device `System.loadLibrary` for every kept lib after filtering; re-run 16 KB alignment + zipalign gate in CI.
