# Tablet / HyperOS Scoping Audit — Wave 22 Report

## Scope inspected
`DeviceProfiles.kt`, `DesktopEnvironment.kt`, `CapabilitySnapshot.kt`, `XiaomiFeatureFlags.kt`, `MirrorService.kt` (scoping/metrics/display/deck-key sites), `DesktopModeConfigurator.kt`, `SessionJournal.kt`, `Watchdog{Client,Daemon,Protocol}.kt`, `DisplayMirrorBackend.kt`, `plasma/CompositedWindowShell.kt`, `DisplayEnvironmentSettings.kt`, `DiagnosticExport.kt`, `MainActivity.kt`, `README.md`, `docs/architecture/HYPEROS_3_COMPATIBILITY_ANALYSIS.md`. Static review only; no builds/edits.

## Top 10 practical issues

1. **P0 — Scoped match is a 4-way AND on unverified identity; silent fallback kills all tablet workarounds.** `DeviceProfiles.kt:69-87` + `DesktopEnvironment.kt:32-45` (`DeviceMatch` ANDs manufacturer + device `duchamp` + fingerprint prefix + minSdk 36). Any mismatch → broad `xiaomi_hyperos` (`DeviceProfiles.kt:85-87`): no `pinMetrics`, no `maxRateApplicationDisplays`, no laptop direct display, no `pinPhysicalMouseToDesktop`, no `directDeckKeyboardToApp`. Ground-truth capture still missing (analysis doc, README device table has no Redmi Pad Pro 5G). **Check:** diagnostic `capability-snapshot.txt` must show `matchedRuleId: xiaomi_redmi_pad_pro_5g`, `environmentId: xiaomi_redmi_pad_pro_5g`, `recommendedBackend: E`. `scopedDeviceProfile: supported` is NOT sufficient — `CapabilitySnapshot.kt:133-135` returns true for the broad Xiaomi rule too. **Fix:** capture `adb shell getprop ro.product.device ro.product.model ro.build.fingerprint ro.product.manufacturer`; add `models=setOf("24094RB9C", …)` or drop `fingerprintPrefixes` (device+manufacturer is already narrow).

2. **P0 — Snapshot report omits `fingerprint`/`product`, so issue #1 is undiagnosable from the export.** `CapabilitySnapshot.kt:38-54` prints manufacturer/brand/model/device/sdk only. **Fix (low-risk):** add `product:` and `fingerprint:` lines to `toReportLines()`.

3. **P1 — 120 Hz app windows are gated by an OFF-by-default experimental toggle.** `CompositedWindowShell.kt:1276-1286` returns null unless `DisplayEnvironmentSettings.maximumMirrorRefreshRateEnabled()`; that is pref `dextop_display_environment` → `experimental_maximum_mirror_refresh_rate`, default `false` (`DisplayEnvironmentSettings.kt:25,97-101,143-144`). `maxRateApplicationDisplays=true` alone gives 60 Hz windows on the 12.1" 120 Hz panel. **Check:** diagnostic `supportsInternal120Hz` and `forceInternal120Hz`; `dumpsys display | grep -i refresh`. **Fix (low-risk):** auto-enable for scoped tablet when `supportsInternal120Hz()` and record/restore via WAL.

4. **P1 — Two documented flags are dead code.** `xiaomi_tablet_touch_mode` and `xiaomi_topology_layout` are read in `XiaomiFeatureFlags.kt:26-32` but have ZERO readers repo-wide (grep). README:166-167 promises escape hatches for broken touch injection / topology parcel layout; users changing them see no effect. **Fix (low-risk):** remove from README/XiaomiFeatureFlags, or wire to touch/topology code before release.

5. **P1 — All five safe kill switches are unreachable in a release build.** No method channel or UI setter writes `FlutterSharedPreferences` `flutter.xiaomi_*` keys (only `flutter.window_manager` at `MainActivity.kt:200-205`); no Dart references. Only `forceFreeform`, `pinMetrics`, `laptopDirectDisplay` are actually consumed (`MirrorService.kt:12176,12208,12211,12741,12516,12712,13387`). **Fix (low-risk):** expose a debug method channel or mark them build-time/dev-only in docs.

6. **P1 — HyperOS metric pinning is scope+flag gated; losing either reverts to shrunken portrait desktop / pointer strip.** `MirrorService.kt:12208,12516,12712,13387`. `xiaomi_pin_metrics=false` or broad-profile fallback → HyperOS re-reports phone size/density; live resize path (`13387-13395`) falls back to `clearForcedDisplaySize`. **Logs:** OperationLog `XiaomiMetrics` = `… applied` / `… unavailable/rejected` / `verify display=<id> requested=… real=…`; `wm size -d <id>`, `wm density -d <id>` via privileged shell. **Fix:** keep size/density pinning unconditional for the scoped tablet; treat flag as density-only kill switch.

7. **P2 — Selecting SYSTEM window manager disables the direct-display workaround and reopens the HyperOS overlay bugs.** `useDirectPlasmaDisplay()` (`MirrorService.kt:12174-12179`) requires selection ∈ {DEXTOP_PLASMA_V2, DEXTOP_BOOK} and `!laptopModeActive || (scoped && xiaomiFlags.laptopDirectDisplay)`. SYSTEM → overlay path → SecondaryDisplayLauncher / portrait override. Default `flutter.window_manager=dextop_book` is written only once (`MainActivity.kt:200-205`). **Fix:** warn/steer back to DEXTOP_BOOK for this profile; log selection in `PlasmaShell`.

8. **P2 — WAL rollback is shell-only and the capability probe overclaims privileges.** `SessionJournal.kt:363-381` restores `wm` entries solely via `privileged.execute`; if Shizuku is dead after a HyperOS kill, restore fails → journal kept → forced size/density persist until manual repair (`MainActivity.kt:1331-1347`). `CapabilitySnapshot.kt:183-184` reports `writeSecureSettings: supported` whenever the Shizuku binder exists (not an actual permission check); `:128-132` probes `IWindowManager.setWindowingMode` while code uses shell `cmd window`/`wm` (`DesktopModeConfigurator.kt:134-140`). Windowing-mode and rotation changes are not watchdogged (`WatchdogProtocol.kt:84-103` allowlist only `settings` + `wm size|density`; `SessionJournal.kt:82-127` skips `rotation`). **Fix:** in-process `IWindowManager` clear fallback; probe a real secure read; journal windowing commands.

9. **P2 — Detached watchdog can die silently on HyperOS's aggressive background killing.** `WatchdogClient.kt:37-47` launches `nohup setsid app_process` with no foreground component; after daemon death `send()` (`65-75`) reconnects, throws on missing listener, and `armWatchdog` only logs (`SessionJournal.kt:129-132`) — protection is lost with no user signal. `/proc/<pid>/stat` liveness check fails closed on SELinux denial (`WatchdogDaemon.kt:139-146`), so only the 15 s heartbeat deadline fires. Receipts in `/data/local/tmp/dextop/watchdog` are never pruned; `wallpaper` actions are `handledByApp` and skipped by `fireAndExit` (`WatchdogDaemon.kt:148-161`). **Fix:** surface watchdog state in diagnostics; require HELLO_ACK before `ARM`; keep app heartbeat as primary.

10. **P3 — Small correctness gaps.** `claimForcedFreeformGlobals()` (`DesktopModeConfigurator.kt:106-117,174-179`) consumes the one-shot claim even if the first shell write fails → no retry on later displays. Deck keys are dropped when `plasmaShell` is not yet a `CompositedWindowShell` despite "only route, no fallback" doc (`MirrorService.kt:11734-11740`). `CapabilitySnapshotEngine.invalidate()` has no callers (`CapabilitySnapshot.kt:75-81`); input probes are attach-time only. `recommendedBackend` is advisory only — no consumer selects Backend E at runtime (`CapabilitySnapshot.kt:186-199`).

## Exact settings / flags / logs

- **Export:** Settings → App information → Operation log → Export ZIP → `capability-snapshot.txt` / `diagnostic-report.txt` (`DiagnosticExport.kt:54-58`, `DiagnosticReport.kt:88`, `MainActivity.kt:752`).
- **Expect in snapshot:** `device: duchamp`, `matchedRuleId: xiaomi_redmi_pad_pro_5g`, `recommendedBackend: E`, `maxRefreshRate: 120.0Hz` (`CapabilitySnapshot.kt:114-117`), `scopedDeviceProfile: supported detail=xiaomi_redmi_pad_pro_5g`.
- **Prefs file `FlutterSharedPreferences`:** `flutter.xiaomi_force_freeform=true`, `flutter.xiaomi_pin_metrics=true`, `flutter.xiaomi_laptop_direct_display=true`, `flutter.xiaomi_tablet_touch_mode=direct` (dead), `flutter.xiaomi_topology_layout=` (dead), `flutter.window_manager=dextop_book`.
- **Prefs file `dextop_display_environment`:** `experimental_maximum_mirror_refresh_rate=true` (needed for 120 Hz windows), `include_dextop_topology`, `software_cursor_fallback`.
- **OperationLog categories:** `CapabilityProbe`, `DesktopMode` (`windowing display=… strategy=… success=…`, `windowing reapply …`), `XiaomiMetrics`, `DisplayBackend`, `XiaomiMetrics verify`, `PlasmaShell`, `SessionJournal`, `DisplayEnvironmentSettings`.
- **logcat tags:** `DextopMirror`, `DextopSessionJournal` (`watchdog arm failed`, `watchdog ack failed`, `restore incomplete; journal kept`). Watchdog daemon log: `/data/local/tmp/dextop-watchdog.log`.
- **adb:** `adb shell wm size -d <id>; adb shell wm density -d <id>; adb shell settings get global enable_freeform_support; adb shell dumpsys display`.

## Low-risk fixes before release
1. Add `product`/`fingerprint` to `CapabilitySnapshot.toReportLines()`.
2. Relax scoped match (add 5G model, drop fingerprint AND) + log matched rule id on Xiaomi devices.
3. Remove dead flags from README/`XiaomiFeatureFlags` or wire them; expose live flag setter or document as dev-only.
4. Auto-enable `experimental_maximum_mirror_refresh_rate` for the scoped tablet when 120 Hz is supported, with WAL-backed restore.
5. Surface watchdog arm/ack failure in `DiagnosticReport`; require HELLO_ACK before considering ARM successful.

## Risks / device testing needed
Ground-truth ADB identity capture on the physical Redmi Pad Pro 5G (HyperOS 3 / API 36) is still mandatory; confirm rule match, 120 Hz on both mirror and app displays, forced metric persistence after kill -9, and watchdog rollback with Shizuku stopped. USB 2.0 has no DP Alt Mode, so validate only virtual/wireless display paths.
