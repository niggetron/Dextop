## Scope inspected
Web-only research (no local build/source edits). Areas: Android 16 (API 36) `Settings.Global` desktop/freeform keys + OEM handling; atomic crash-safe preference/JSON persistence; StrictMode blocking-IPC detection; coroutine structured concurrency for foreground services; `https://github.com/android/skills` skill inventory. ## Findings (severity, BRIEF-referenced file, why it matters on API 36/HyperOS, concrete fix)

- **P0 — BUG-01 `SessionJournal` (restore only 3/7 keys).** The 7 SDK-36 desktop/windowing keys are `@hide`/`@Readable` constants in `Settings.Global`, written via `settings put global` / `Settings.Global.putInt()` needing `WRITE_SECURE_SETTINGS` (shell/privileged only):
  1. `force_resizable_activities` (`DEVELOPMENT_FORCE_RESIZABLE_ACTIVITIES`)
  2. `enable_freeform_support` (`DEVELOPMENT_ENABLE_FREEFORM_WINDOWS_SUPPORT`)
  3. `override_desktop_experience_features` (`DEVELOPMENT_OVERRIDE_DESKTOP_EXPERIENCE_FEATURES`)
  4. `override_desktop_mode_features` (`DEVELOPMENT_OVERRIDE_DESKTOP_MODE_FEATURES`)
  5. `force_desktop_mode_on_external_displays` (`DEVELOPMENT_FORCE_DESKTOP_MODE_ON_EXTERNAL_DISPLAYS`)
  6. `display_density_forced` (`DISPLAY_DENSITY_FORCED`)
  7. `enable_non_resizable_multi_window` (`DEVELOPMENT_ENABLE_NON_RESIZABLE_MULTI_WINDOW`)
  Sources: [AOSP Settings.java android-16.0.0_r1 L13979-14037](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-16.0.0_r1/core/java/android/provider/Settings.java), [WindowManagerService.java: mForceDesktopModeOnExternalDisplays reads Settings.Global](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-16.0.0_r1/services/core/java/com/android/server/wm/WindowManagerService.java), [AOSP diff adding desktop-mode override docs](https://android.googlesource.com/platform/frameworks/base.git/+/6d7332e469b3c13ce98082a5963acd185e4ec517%5E%21). On Xiaomi Redmi Pad Pro 5G / HyperOS 3 (minSdk 33), OEM skins add their own parallel keys (MiUI/Xiaomi "second space"/freeform, Samsung DeX `force_desktop_mode_on_external_displays`) and may ignore/reset AOSP keys after reboot or OTA — so the journal must snapshot **all** mutated keys generically, not a hardcoded 3. Fix: WAL JSON with `{key, namespace(global|secure|system), value, previousValue, userId, timestamp, schemaVersion}` for every key touched, restore all entries, verify by re-reading each key (Settings.Global.getString) and record mismatches; gate all writes behind `Typed PrivilegeGate` since WRITE_SECURE_SETTINGS is not granted to normal third-party apps.
  - Android 16 behavior: large-screen apps are resizable by default and orientation/aspect constraints ignored, so `force_resizable_activities` is less critical on the 12.1" tablet, but `override_desktop_experience_features` and `force_desktop_mode_on_external_displays` govern external-display desktop mode and are the ones HyperOS may override ([Android 16 behavior changes](https://developer.android.com/about/versions/16/behavior-changes-16), [Android 16 desktop windowing analysis](https://jonesconsortium.com/android-16-architecture-changes)).
  - OEM note: Android 16 desktop mode is built on Samsung DeX foundations; Xiaomi/Vivo/OPPO ship proprietary desktop implementations with non-AOSP keys — treat key names as a versioned adapter, probe before trusting ([Google/Android 16 desktop mode built on DeX](https://medium.com/vertical-bar-media/google-unveils-android-16s-desktop-mode-built-on-samsung-dex-vbm-1b4aae1a9f12), [XDA ADB tweak keys](https://xdaforums.com/t/samsung-dex-on-stock-firmware-wired-dex.4801976)).

- **P0 — BUG-01 persistence substrate (WAL JSON must be crash-safe).** Do **not** use plain `SharedPreferences` for the WAL: `apply()` blocks the UI thread on `fsync()`, `commit()` is synchronous, both swallow errors, and SharedPreferences offers no atomicity/corruption guarantees; DataStore docs explicitly note it "encourages StrictMode violations" and is not durable on apply ([SharedPreferences→DataStore guidance](https://developer.android.com/codelabs/android-preferences-datastore), [DataStore KMP API docs](https://androidx.github.io/kmp-eap-docs/libs/androidx.datastore/datastore-core/androidx.datastore.core/-data-store), [SharedPreferences lacks atomicity](https://dev.to/myougatheaxo/datastore-vs-sharedpreferences-why-your-ai-generated-app-already-uses-the-right-one-2cc4)). Fix (dependency-light, no new deps): `android.util.AtomicFile` (API 17) writes to `<name>.new`, then `finishWrite()` closes, `fsync`s and renames; `openRead()` prefers `.new` if base is incomplete; `failWrite()` deletes `.new`; you must provide your own mutual exclusion ([AtomicFile API ref](https://developer.android.com/reference/android/util/AtomicFile), [why fsync-before-rename matters](https://github.com/growthbook/growthbook-kotlin/issues/240)). Append-only WAL = one JSON line per mutation, fsync each record, periodic compact snapshot via `AtomicFile`, replay on startup. Serialize all WAL access on a single `CoroutineScope(Dispatchers.IO)` mutex. DataStore (Proto) is acceptable for non-WAL UX prefs but is coroutine/Flow-based, adds dependencies, and still must not run on the main thread.

- **P0 — BUG-02 `DesktopModeConfigurator.configureDisplay()` blocking `wm` IPC on main looper.** StrictMode detects accidental disk/network on main thread and Binder calls via `detectBlockableCalls`/`detectBinderCalls(...)` (and custom `StrictMode.OnThreadViolationListener`), with `penaltyLog()`/`penaltyDeath()`; note JNI/native calls are NOT reliably detected ([StrictMode reference](https://developer.android.com/reference/android/os/StrictMode), [StrictMode source, "best effort ... disk or network access from JNI calls won't necessarily trigger it"](https://android.googlesource.com/platform/frameworks/base/+/edc31509c2ff8cba86f30c836934d32a3e249dec/core/java/android/os/StrictMode.java)). Fix: `sessionScope = CoroutineScope(SupervisorJob() + Dispatchers.IO)` created per session; wrap `wm`/`settings put` shell calls in `withContext(Dispatchers.IO)`, add timeout (`withTimeout(...)`) and `currentCoroutineContext().ensureActive()` cancellation; call `sessionScope.cancel()` on teardown. Enable StrictMode in debug builds with `ThreadPolicy.Builder().detectAll().penaltyLog()` + `VmPolicy` and route violations to Crashlytics/logcat. Apply official static ANR audit skill `performance/anr-audit-and-fix` to prove which thread actually blocks.

- **P1 — BUG-03 `MirrorService.kt` God object / FGS lifecycle.** Structured concurrency: a parent `Job` does not complete until every child completes, and failure of any child in `coroutineScope` cancels all siblings; use `SupervisorJob` for independent domain services so one failure doesn't tear down the session ([Kotlin cancellation and timeouts](https://kotlinlang.org/docs/coroutines-cancellation.html), [SupervisorJob semantics](https://revenuecat.com/blog/engineering/supervisorjob-kotlin), [Android coroutines guide](https://developer.android.com/kotlin/coroutines/coroutines-adv)). Fix: decompose MirrorService into domain services each owning a `SupervisorJob` child under a single session `CoroutineScope`; keep the foreground service as an owner of the scope (`onCreate` create, `onDestroy` cancel), expose state as `StateFlow` consumed by Compose via `collectAsStateWithLifecycle`; service must hold a `WakeLock`/FGS notification only while scope is active. Protect its exported IPC surface: `android:exported="false"` for private components, `Binder.getCallingUid()` + `hasSigningCertificate()` for bound callers, never trust intent-extra package names, and `enforceCallingPermission()` (not `...CallingOrSelfPermission`) on mutating Binder methods ([android/skills security/android-permissions-security SKILL.md](https://raw.githubusercontent.com/android/skills/main/security/android-permissions-security/SKILL.md)).

## Deliverable (design sketch + web citations)

**Concrete dependency-light patterns for Dextop**

1. **WAL writer** — single `AtomicFile` `session_journal.json` + append-only `session_journal.wal` (JSONL):
   ```kotlin
   class SessionJournal(private val atomic: AtomicFile, private val io: CoroutineDispatcher) {
     private val mutex = Mutex()
     suspend fun mutate(e: KeyMutation) = withContext(io) { mutex.withLock {
       val os = atomic.startWrite()
       try { os.write((readAll() + e).toJsonLine().toByteArray()); atomic.finishWrite(os) }
       catch (t: Throwable) { atomic.failWrite(os); throw t }
     }}
   }
   ```
   `AtomicFile.finishWrite()` = close+fsync+rename; `startWrite()` targets `.new`; no file locking — serialize with `Mutex` ([AtomicFile](https://developer.android.com/reference/android/util/AtomicFile)). Record every one of the 7 keys above with previous value; restore all. For FGS robustness pair with a 15 s detached watchdog that re-reads settings and re-enqueues failed mutations (per BRIEF).
2. **IPC off main thread** — `sessionScope` + `withContext(Dispatchers.IO)` + `withTimeout` + `ensureActive()` + `cancel()` in teardown; StrictMode `detectAll().penaltyLog()` in debug to catch regressions ([StrictMode](https://developer.android.com/reference/android/os/StrictMode), [ANR audit skill](https://raw.githubusercontent.com/android/skills/main/performance/anr-audit-and-fix/SKILL.md)).
3. **Settings access** — versioned `SettingsAdapter` (API 33 vs 36 vs OEM HyperOS), each write logged to WAL and verified by read-back; all keys are `@hide` so must be referenced as string literals, never as compile-time `Settings.Global.*` constants (hidden API non-SDK restrictions; minSdk 33 target). ADB capture for M1: `adb shell settings list global` / `dumpsys window` / `cmd window` ([Android CLI skill](https://raw.githubusercontent.com/android/skills/main/devtools/android-cli/SKILL.md), [device-ai/appfunctions ADB testing ref](https://raw.githubusercontent.com/android/skills/main/device-ai/appfunctions/references/adb-interaction-testing.md)).

## Risks / device testing needed
- Hidden `@hide` settings keys: confirm all 7 are writable/readable on HyperOS 3; OEM may rename, ignore, or reset on reboot/OTA — probe via `adb shell settings list global` before/after reboot and after display hotplug.
- `WRITE_SECURE_SETTINGS` cannot be self-granted to a normal app; requires ADB/privileged install or system signature — keep behind `PrivilegeGate`, degrade gracefully to backend F (compatibility) if unavailable.
- StrictMode does not reliably catch JNI/native Binder calls; pair with ANR trace triage on-device.
- AtomicFile gives integrity, not inter-process locking — single-writer invariant must hold across FGS restart; test crash-injection (kill during write) WAL replay and 15 s watchdog on real Redmi Pad Pro 5G.
- Verify external-display desktop mode on actual hardware (USB-C/DP + wireless display), since Android 16 semantics differ from legacy freeform and from Samsung DeX/HyperOS.
