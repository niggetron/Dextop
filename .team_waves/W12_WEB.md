# Web Agent W12C — Wave 12 Report

## Scope inspected
Web-only; no local source touched. Target: Redmi Pad Pro 5G / Android 16 (API 36) / HyperOS 3 / arm64 / minSdk 33. Sources cited inline.

## Findings

**P1 — Vanilla Smithay is not an Android backend; a fork/patch is required.** Winland-Android (closest production analogue: Smithay compositor in-process, Kotlin/Compose UI, UniFFI+JNI, PRoot chroot) uses a **patched** Smithay vendored at `lib/smithay` with features `wayland_frontend, desktop, wayland-server, renderer_glow, xwayland, backend_egl, renderer_gl` plus `khronos-egl` (dynamic) + `gl 0.14`; socket created in app data dir and bind-mounted into chroot; output to SurfaceView via EGL/AHB or Vulkan+Zink/Turnip. https://github.com/eirkkk/winland-Android/blob/main/README.md ; https://raw.githubusercontent.com/eirkkk/winland-Android/main/native/Cargo.toml . Alternative wlroots lineage: https://github.com/Xtr126/tinywl-ANativeWindow , https://github.com/Xtr126/wlroots-android-bridge . Why it matters: GBM/libseat/DRM-master assumptions break on Android; budget for a maintained patch set, not a drop-in crate. Fix: M6 uses an in-process patched Smithay port with a narrow `AndroidOutput` trait (EGL→AHB), no libseat/GBM.

**P1 — Rust NDK binding gap.** Safe `ndk` 0.9.0 has `hardware_buffer`, `hardware_buffer_format`, `native_window`, `surface_texture`, `sync` but **no** `surface_control`, `choreographer`, or `performance_hint` modules. `ndk-sys` 0.6.0 raw FFI *does* expose `AChoreographer*` (incl. `postVsyncCallback`, `registerRefreshRateCallback`, frame-timeline accessors), `APerformanceHint*`, `AWorkDuration`, `ANativeWindow_setFrameRate` — but **no** `ASurfaceControl`/`ASurfaceTransaction`. https://docs.rs/ndk/latest/ndk/ ; https://docs.rs/ndk-sys/latest/ndk_sys/ (verified fn list). Fix: one versioned `android-ffi` crate: safe `ndk` wrappers for AHB/ANativeWindow, hand-written `extern "C"` (or bindgen from NDK ≥ r28 `surface_control.h`) for ASurfaceControl/ASurfaceTransaction only; feature-gated, no `dlsym` on hot path (kills BUG-05's dlopen/dlsym/dlclose-per-allocation).

**P2 — Frame pacing / 120 Hz.** `AChoreographer_getInstance` API 24, `postFrameCallback64` 29, `postVsyncCallback` + frame timelines 33, `registerRefreshRateCallback` 30. `ASurfaceTransaction_setFrameRate` API 30, `WithChangeStrategy` 31; `ANativeWindow_setFrameRate` 31; `setBufferWithRelease`+`OnBufferRelease` API 36. https://developer.android.com/ndk/reference/group/choreographer ; https://android.googlesource.com/platform/frameworks/native/+/refs/tags/android-15.0.0_r20/include/android/surface_control.h . Why: HyperOS refresh may differ from the 120 Hz panel spec; never hardcode. Fix: drive render from `postVsyncCallback` (available at minSdk 33), pick preferred timeline via `AChoreographerFrameCallbackData_*`, feed `setFrameRate(0.0f, COMPATIBILITY_NATIVE)` initially, re-evaluate on refresh-rate callback; `ANativeWindow_setFrameRate` as API-31 fallback behind adapter.

**P2 — ADPF in Rust.** Raw FFI via `ndk-sys` (`APerformanceHint_getManager`, `createSession`, `reportActualWorkDuration`, `updateTargetWorkDuration`, `setNativeSurfaces`, `isFeatureSupported`). `getPreferredUpdateRateNanos` is deprecated in API 36 — gate on `APerformanceHint_isFeatureSupported(APERF_HINT_SESSIONS/GRAPHICS_PIPELINE/SURFACE_BINDING)`, not on that call. Sessions are not thread-safe; TIDs must be long-lived. https://developer.android.com/ndk/reference/group/a-performance-hint ; https://source.android.com/docs/core/perf/performance-hint-api . Fix: optional session for render thread with 8.33 ms target at 120 Hz; silently degrade on `nullptr`/`ENOTSUP`/`EPIPE` (OEM battery policy may neuter it).

**P1 — 16 KB alignment is a release blocker, not a nicety.** Apps targeting API 35+ must support 16 KB page sizes on Google Play (enforcement from 2027-02-01). NDK r28+ links 16 KB-aligned by default; with r27- use `-Wl,-z,max-page-size=16384 -Wl,-z,common-page-size=16384`; AGP ≥ 8.5.1; verify `LOAD align 2**14`, `GNU_RELRO end % 0x4000 == 0`, `zipalign -c -P 16 -v 4`, `check_elf_alignment.sh`; replace `PAGE_SIZE` with `sysconf(_SC_PAGESIZE)`. https://developer.android.com/guide/practices/page-sizes . Fix (Rust): NDK r28+ and `.cargo/config.toml` `[target.aarch64-linux-android] rustflags = ["-C","link-arg=-Wl,-z,max-page-size=16384","-C","link-arg=-Wl,-z,common-page-size=16384"]`; assert in CI after Gradle (cargo-ndk/Gradle can override rustflags), plus RELRO check for `libdextop_core.so` and all C PRoot libs.

**P0 — dmabuf→AHB is hidden/VNDK, not public NDK.** Public `android/hardware_buffer.h` has only `AHardwareBuffer_allocate/acquire/release/lock/unlock/describe/getId/send|recvHandleFromUnixSocket`; `AHardwareBuffer_createFromHandle` + `AHardwareBuffer_getNativeHandle` live in `vndk/hardware_buffer.h` (vendor NDK) and need a gralloc-specific `native_handle_t`. https://android.googlesource.com/platform/frameworks/native/+/master/libs/nativewindow/include/vndk/hardware_buffer.h ; https://developer.android.com/ndk/reference/group/a-hardware-buffer . `tinywl-ANativeWindow` hardcodes `cros_gralloc_handle` (ChromeOS gralloc) — will not work on MediaTek/HyperOS gralloc. https://github.com/Xtr126/tinywl-ANativeWindow/blob/main/buffer_utils.cpp . Safe zero-copy is the *other* direction: allocate AHB with `AHardwareBuffer_allocate` (usage `GPU_SAMPLED_IMAGE|GPU_FRAMEBUFFER`), bind with `eglGetNativeClientBufferANDROID`→`eglCreateImageKHR`, render directly into it, submit via `ASurfaceTransaction_setBuffer`/`setBufferWithRelease` — GPU→SurfaceFlinger stays zero-copy using only public APIs. https://developer.android.com/ndk/reference/group/a-hardware-buffer . Fix: make dmabuf import an opt-in versioned adapter with runtime capability probe + blit fallback; never on critical path; replace broker with long-lived AF_UNIX + `AHardwareBuffer_sendHandleToUnixSocket` and caller-UID/SELinux checks (no `/proc/<pid>/environ`, no 64 KB stack buffer, no per-call dlopen).

## Deliverable — minimal safe path for M6
1. **M6a (public-only core):** patched Smithay fork → EGL/GLES renderer → NDK-allocated AHBs → SurfaceView/ANativeWindow. UniFFI control plane + raw JNI data plane unchanged. Frame loop: `AChoreographer_postVsyncCallback` → render → transaction; `ASurfaceTransaction_setFrameRate` behind adapter; ADPF optional behind `isFeatureSupported`.
2. **M6b:** add thin ASurfaceControl adapter (cursor/overlay layers, API 29 base / 36 release callback) via hand-declared `extern "C"`; keep ANativeWindow fallback. Reuse existing 64 KB SPSC input ring; do not touch AHB on input path.
3. **Build/CI:** NDK r28+, AGP 8.5.1+, 16 KB rustflags + ELF/RELRO/zipalign assertions in GitHub Actions; no local builds.
4. **Explicitly defer:** VNDK `createFromHandle` dmabuf import, Zink/Turnip Vulkan path, any `/proc`-based peer auth.

## Risks / device testing needed
- Exact API-36 symbol availability on HyperOS 3 (ASurfaceControl setFrameRate / setBufferWithRelease / ADPF features) — probe at runtime, never assume.
- Smithay patch maintenance cost and XWayland/power draw on a 12.1" 120 Hz tablet; measure with Perfetto + `dumpsys SurfaceFlinger --latency`.
- Verify `getconf PAGE_SIZE` on device (likely 4096); still ship 16 KB-aligned libs for Play and 16 KB Cuttlefish CI.
- Validate AHB buffer-release lifecycle (no dropped frames / use-after-free) with `OnBufferRelease` under rotation and session teardown.
- Confirm gralloc support for `AHARDWAREBUFFER_FORMAT_R8G8B8A8_UNORM` + `GPU_SAMPLED_IMAGE|GPU_FRAMEBUFFER` via `AHardwareBuffer_isSupported` before allocating.
