# Web Agent W5C — Wave 5 Report

## Scope inspected
Web-only research: detached shell `app_process` on Android 14–16, `LocalServerSocket`/abstract sockets + `SO_PEERCRED`, `pidfd_open` on bionic, HyperOS 3 process killing, watchdog/dead-man patterns. No builds, no source edits.

## Findings

**P0 — SIGKILL is uncatchable; no in-process watchdog can survive its own kill.**
`SIGKILL`/`SIGSTOP` cannot be caught, blocked, or ignored ([signal(7)](https://man7.org/linux/man-pages/man7/signal.7.html)). `nohup` only ignores SIGHUP; `setsid` only creates a new session with no controlling terminal — neither protects against SIGKILL or cgroup/UID-scoped kills ([setsid guide](https://pocketclaw.dev/guides/setsid-gateway), [SO: adb nohup](https://stackoverflow.com/questions/36438572/launching-a-persistent-background-process-on-android-from-linux)). Therefore the blueprint's "15 s detached watchdog" must be a **separate process in a different UID** (e.g. `adb shell`/Shizuku shell UID 2000), not a thread in the payload. Need device test to confirm.

**P0 — Detachment does not escape UID/cgroup kills.** `app_process` is a normal executable (`/system/bin/app_process64`) runnable from shell; non-zygote mode calls `RuntimeInit.main()` (`--application`, `--nice-name`) then `IPCThreadState::stopProcess()` on return ([AOSP app_main.cpp](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-14.0.0_r25/cmds/app_process/app_main.cpp), [overview](https://blog.51cto.com/u_16163453/9885537)). A shell-launched child keeps its launching UID; even after reparenting to init on shell death it retains that UID, and Android kills by UID/group, so `am force-stop` / `am kill-all` of the parent app still kills a `setsid`-detached child of that app ([haydn-server ADB matrix, "am kill-all = red line"](https://github.com/qingxuan233/haydn-server/blob/main/docs/20-server/19-ADB%E4%B8%BA%E6%9C%8D%E5%8A%A1%E5%99%A8%E8%AE%A9%E8%B5%84%E6%BA%90%E6%96%B9%E6%A1%88.md)). Launch the watchdog from a **different UID** than the Compose app.

**P1 — HyperOS 3 has several independent kill layers, none fully disableable.** Native Doze + App Standby + `cached_apps_freezer` (cgroup freezer) + Xiaomi's proprietary **Greezer** proactive freezing + BroadcastQueue denial + lock-screen cleanup + Security cleaner force-stop; diagnosis via `adb logcat -b events | grep am_kill` (reason e.g. `LockScreenClean`) ([HyperOS 3 field notes](https://github.com/miguel-rosso/xiaomi-fixes-hyperos3---Chinese-ROM-), [Xiaomi kill-event doc summary](https://sekin.in/miui-killing-background-apps-on-xiaomi-including-hyperos-how-to-fix-it)). Community mitigation is three settings — Autostart ON, per-app battery "No restrictions", Recents lock — but these reduce, never eliminate, kills ([dontkillmyapp/Xiaomi](https://dontkillmyapp.com/xiaomi), [Shizuku Xiaomi guide](https://shizukudownload.com/guides/xiaomi)). Foreground service + wake lock alone are insufficient.

**P1 — Phantom process killer reaps >32 forked children system-wide on Android 12–16, including HyperOS.** `PhantomProcessList.trimPhantomProcessesIfNecessary()` kills phantom children and can also kill the parent if its oom_adj is worse than another app's ([AOSP PhantomProcessList.java](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/master/services/core/java/com/android/server/am/PhantomProcessList.java), [agnostic-apollo reference](https://raw.githubusercontent.com/agnostic-apollo/Android-Docs/master/en/docs/apps/processes/phantom-cached-and-empty-processes.md)). Android 14+ mitigation: Developer options → **"Disable child process restrictions"** (sets `persist.sys.fflag.override.settings_enable_monitor_phantom_procs=false`; reverts if Developer options are turned off); older: `settings put global settings_enable_monitor_phantom_procs false` ([Andronix signal-9 fix](https://docs.andronix.app/troubleshooting/signal-9), [Ivon's blog](https://ivonblog.com/en-us/posts/fix-termux-signal9-error)). Critical for a PRoot/Wayland backend that forks many children.

**P1 — `pidfd_open` is available on bionic since API 31 (target API 36 is safe).** `<sys/pidfd.h>` declares `pidfd_open`, `pidfd_getfd`, `pidfd_send_signal`, all `__INTRODUCED_IN(31)`; added as syscall wrappers in "S / API 31" ([bionic pidfd.h](https://android.googlesource.com/platform/bionic/+/master/libc/include/sys/pidfd.h), [bionic status](https://android.googlesource.com/platform/bionic/+/HEAD/docs/status.md), [SYSCALLS.TXT](https://android.googlesource.com/platform/bionic/+/HEAD/libc/SYSCALLS.TXT)). A pidfd becomes poll-readable when its process exits, avoiding PID-reuse races and `wait()` on a non-child; fd is CLOEXEC. Use it in the watchdog with `poll`/`epoll` for deterministic death detection; keep an abstract-socket heartbeat + `/proc/<pid>` poll as fallback per the "isolate hidden APIs behind versioned adapters" rule.

**P1 — `LocalServerSocket` = Linux abstract namespace; `SO_PEERCRED` gives kernel-attested pid/uid/gid.** `LocalServerSocket(String)` binds in the abstract namespace (no filesystem path, no umask/permission bits; name vanishes when last FD closes) ([Android API ref](https://developer.android.com/reference/android/net/LocalServerSocket), [unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html)). `LocalSocket.getPeerCredentials()` → JNI `getsockopt(fd, SOL_SOCKET, SO_PEERCRED, &ucred, ...)` captured at `connect()` time ([Android API ref](https://developer.android.com/reference/android/net/LocalSocket), [AOSP JNI](https://android.googlesource.com/platform/frameworks/base/+/master/core/jni/android_net_LocalSocketImpl.cpp), [AndroidIDE usage: allow only own UID or UID 0](https://github.com/AndroidIDEOfficial/AndroidIDE/blob/dev/termux/shared/src/main/java/com/termux/shared/net/socket/local/LocalServerSocket.java)). Caveats: abstract sockets have no access control, so any local process can connect/claim the name early — use a hard-to-guess, versioned name plus `SO_PEERCRED` UID allowlist; the `Credentials` javadoc notes "root peers may lie", so this is not a boundary against root. NDK (no-Java) AF_UNIX abstract sockets work; filesystem sockets fail with `Read-only file system` ([SO](https://stackoverflow.com/questions/74297407/can-i-use-a-unix-domain-socket-on-android)).

**P2 — AOSP watchdog pattern: heartbeat timeout → stack dump → kill self, supervisor restarts.** AOSP `Watchdog` pings monitored threads, waits 30 s, dumps stacks at half-time, waits to 60 s, then `Process.killProcess(myPid()); System.exit(10)` so the parent/init restarts the service ([Watchdog.java](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/services/core/java/com/android/server/Watchdog.java)). Shizuku's "NightDog" variant beats on the main looper every 5 s, checks freshness against a 60 s timeout on a daemon thread, logs the stalled thread's stack, then kills self, and also uses `IBinder.linkToDeath` on system services ([shevery nightdog](https://github.com/HmnDev-Tech/shevery/blob/main/docs/nightdog.md)). Adopt: payload emits heartbeat to watchdog over abstract socket at ~1 s; watchdog's 15 s deadline → dump WAL/stack → `pidfd_send_signal(SIGKILL)`/let it die → re-`app_process` launch → FSM replays atomic WAL. Note: `linkToDeath` recipients inside the killed process die with it; keep registration in the watchdog.

## Deliverable — recommendation: what survives kill-9 on HyperOS 3

**Survives a target SIGKILL:**
- A **separate shell-UID watchdog** launched via `setsid`/`nohup` + `app_process` (`setsid app_process64 -Djava.class.path=... --nice-name=dextop_watchdog com.dextop.Watchdog >/sdcard/.../watchdog.log 2>&1 </dev/null &`), reparented to init, whose UID differs from the Compose app and PRoot payload. Parent-shell death / SIGHUP does not touch it.
- Its open **pidfd** (poll-readable on child exit, no PID-reuse race), **abstract socket name** is released immediately (no stale lock file), **`SO_PEERCRED`** of any new connection, and **fsync'd atomic WAL JSON** on disk.
- Kernel state owned by the watcher: wake lock it holds itself, its own Binder death recipients, its log/timer.

**Does not survive:**
- The killed process's signal handlers, in-process watchdog thread, wake lock, Binder/DeathRecipient registrations, unsynced/in-memory WAL edits, StateFlow FSM memory, and its abstract-socket listener (must rebind).
- Anything killed by UID-scoped `am force-stop`/`am kill-all`/MIUI cleaner — including a `setsid`-detached child of the same app UID. `setsid` changes session, not UID or cgroup.
- Reboot: a detached shell process has no autostart. Recovery needs an app with `RECEIVE_BOOT_COMPLETED` + Autostart explicitly enabled (per Xiaomi settings) to re-issue the shell launch, plus Developer options "Disable child process restrictions" kept on.

**Design implications for Dextop M2/M4E:** put the 15 s watchdog in a shell-UID companion (`PrivilegeGate` shell tier), not in the app process or PRoot cgroup; use `LocalServerSocket` + `SO_PEERCRED` UID allowlist for control, `pidfd_open` (API 31+) for liveness, WAL atomic rename + `fsync` for state, `app_process` for relaunch. Explicitly document that HyperOS can still SIGKILL the watchdog itself — target deterministic recovery and WAL restore, not absolute persistence. Do not depend on `MIUI optimization` toggles or root.
