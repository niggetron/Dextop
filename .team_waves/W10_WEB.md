## Findings (P0/P1/P2/P3)

### P0 — 16 KB page alignment is non-negotiable for the `libdextop_core.so` data plane
- Android 15+ supports 16 KB pages on arm64; AOSP builds 16 KB-aligned ELF with `-Wl,-z,max-page-size=16384`. [AOSP](https://source.android.com/docs/core/architecture/16kb-page-size/16kb)
- Google Play requires 16 KB support for updates targeting API 35+ (initial blog: 1 Nov 2025; current cutoff reported as 1 Feb 2027). Dextop targets API 36 → in scope. [Android Developers Blog](https://android-developers.googleblog.com/2025/05/prepare-play-apps-for-devices-with-16kb-page-size.html) · [OTF](https://otf-kit.dev/blog/android-16kb-page-size-feb-2027)
- **NDK r28+ compiles 16 KB-aligned by default**; r27 and older need `-Wl,-z,max-page-size=16384 -Wl,-z,common-page-size=16384`. AGP 8.5.1+ auto-aligns uncompressed shared libs at packaging. [Developer guide](https://developer.android.com/guide/practices/page-sizes) · [July 2025 blog](https://android-developers.googleblog.com/2025/07/transition-to-16-kb-page-sizes-android-apps-games-android-studio.html)
- Two independent checks: ELF `PT_LOAD` `p_align >= 0x4000` (`readelf -lW` / `check_elf_alignment.sh`) AND APK ZIP alignment (`zipalign -c -P 16`); a bundle can pass intermediate APK but fail after bundletool. [xckevin](https://xckevin.com/en/blog/android-16kb-page-size-elf-ndk)
- Rust-specific: a hand-built `libandroid_rust_uniffi.so` came out `UNALIGNED (2^12)` with NDK r27 while JNA's `libjnidispatch.so` was already `ALIGNED (2^16)` — i.e. **your own cdylib is the likely offender, not JNA**. [takusan.negitoro.dev](https://takusan.negitoro.dev/posts/android_15_16kb_page_size)
- Concrete fix: pin NDK r28.x, set AGP >= 8.5.1, add linker flags explicitly in `.cargo/config.toml` as belt-and-braces, replace hardcoded `4096`/`PAGE_SIZE` in C (PRoot/fastpath, cf. BUG-05 64 KB stack buffer + mmap alignment) with `sysconf(_SC_PAGESIZE)`/`getpagesize()`, and run `check_elf_alignment.sh` on every release AAB/APK in CI.
- Device note: Xiaomi is among OEMs offering the 16 KB developer option — validate on the actual Redmi Pad Pro, not only emulator. [Dec 2024 blog](https://android-developers.googleblog.com/2024/12/get-your-apps-ready-for-16-kb-page-size-devices.html)

### P0 — Split the FFI exactly as the blueprint says: UniFFI control plane, raw JNI data plane
- UniFFI packs every argument into a buffer, goes through JNA (itself JNI), unpacks; return repeats in reverse. "Coarse calls belong to UniFFI, hot loops belong to JNI you control." [davthecoder](https://www.davthecoder.com/blog/uniffi-android-kotlin-bindings-for-rust)
- Measured Kotlin/JNA cost: every call taking `RustCallStatus` allocates ~1.5 KB JVM heap + ~3.5–4 µs CPU; preallocated status pointer = 0 B / 80 ns; calls from a non-JVM thread add ~17 µs attach/detach. Methods pay twice (clone call). [uniffi-rs #3011](https://github.com/mozilla/uniffi-rs/issues/3011) · Swift equivalent [uniffi-rs #3013](https://github.com/mozilla/uniffi-rs/issues/3013)
- Raw JNI: primitive call overhead ~3 ns; arrays are copied in one shot (~169 ns/100 doubles); zero-copy via `DirectByteBuffer` or `GetPrimitiveArrayCritical` (no JNI calls or blocking while held). "Design APIs that cross rarely: one chunky call beats a thousand chatty ones." [ffi-bench](https://github.com/muraalee/ffi-bench-napi-jni) · [JNI ByteBuffers](https://www.davthecoder.com/blog/passing-data-kotlin-rust-jni-bytebuffers-zero-copy) · [AOSP Rust patterns](https://source.android.com/docs/setup/build/rust/building-rust-modules/android-rust-patterns)
- Concrete fix for the 64 KB SPSC input ring: map the ring as a Java `DirectByteBuffer` into a Rust `&mut [u8]` through a hand-written `jni` export (one `Java_dextop_..._pollRing()` per frame/batch); never expose per-event functions through UniFFI. Keep all `unsafe` in `jni_bridge.rs`. [softwarepatternslexicon](https://softwarepatternslexicon.com/rust/mobile-development-with-rust/integrating-rust-with-android-jni)
- Do **not** swap UniFFI for BoltFFI in M5 despite claimed 1000× gains — repo created Dec 2025, too immature for this milestone. [boltffi](https://github.com/boltffi/boltffi)

### P1 — cargo-ndk + target/toolchain pins (build recipe)
- Current `cargo-ndk` 4.1.2 (2025-08-09), **MSRV 1.86**, install via `cargo binstall cargo-ndk` in CI to avoid compiling the tool itself; v4 is a thin cargo passthrough, adds `cargo ndk-test`/`ndk-env`, `--link-builtins`, `--link-cxx-shared`, and linker flags for older NDKs re 16 KB. [crates.io](https://crates.io/crates/cargo-ndk) · [CHANGELOG](https://github.com/bbqsrc/cargo-ndk/blob/main/CHANGELOG.md)
- Recipe: `rustup target add aarch64-linux-android x86_64-linux-android` (x86_64 for emulator tests); `ANDROID_NDK_HOME=<ndk r28>` or auto-detected; `cargo ndk -p 33 -t arm64-v8a -o app/src/main/jniLibs build --release` → `jniLibs/arm64-v8a/libdextop_core.so` with no Gradle config. [cargo-ndk README](https://github.com/bbqsrc/cargo-ndk) · [davthecoder setup](https://www.davthecoder.com/blog/rust-android-ndk-toolchain-setup-cargo-ndk)
- `crate-type = ["cdylib"]`; `System.loadLibrary("dextop_core")`; pin NDK API level to minSdk 33 (`-p 33`). [zenn.dev](https://zenn.dev/sakuram_dev/articles/android-app-with-rust)
- Caveat: NDK replaced `libgcc.a` with `libunwind.a` on some setups; if `-lgcc` fails, copy `libunwind.a`→`libgcc.a` (Greptime workaround). [Greptime](https://www.greptime.com/blogs/2025-04-14-rust-in-android-edge-based-practice)

### P1 — UniFFI Kotlin bindings generation (current practice)
- UniFFI 0.32.x. UDL is optional now: `#[uniffi::export]`, derives, and `uniffi::setup_scaffolding!()` replace `build.rs`; records→data classes, enums→enum classes, error enums→sealed exceptions, `Result`→thrown exceptions. [davthecoder](https://www.davthecoder.com/blog/uniffi-android-kotlin-bindings-for-rust)
- Preferred flow: library mode from the built `.so`, no UDL: `cargo run --features=uniffi/cli --bin uniffi-bindgen generate --library target/.../libdextop_core.so --language kotlin --out-dir out/kotlin`; add `[[bin]] uniffi-bindgen` calling `uniffi::uniffi_bindgen_main()`. [muhittincamdali](https://muhittincamdali.com/en/blog/rust-mobil-paylasimli-cekirdek-uniffi) · [uniffi_bindgen docs](https://docs.rs/uniffi_bindgen)
- Gradle wiring options: (a) manual `generate<Variant>UniFFIBindings` Exec task per official guide (bindgen in PATH) [UniFFI Gradle guide](https://mozilla.github.io/uniffi-rs/latest/kotlin/gradle.html); (b) Gobley `dev.gobley.cargo` + `dev.gobley.uniffi` 0.3.7 [Gobley](https://gobley.dev/docs/gradle-plugins/uniffi); (c) Ubique `ch.ubique.uniffi.plugin` 1.3.0 with `compileSdk = 36`, explicit `ndkVersion`. [Ubique](https://github.com/UbiqueInnovation/uniffi-kotlin-multiplatform-bindings)
- Kotlin/JVM bindings need **JNA** (and coroutines) dependencies; UniFFI objects must be explicitly destroyed on Kotlin side. [UniFFI Gradle guide](https://mozilla.github.io/uniffi-rs/latest/kotlin/gradle.html) · [muhittincamdali](https://muhittincamdali.com/en/blog/rust-mobil-paylasimli-cekirdek-uniffi)

### P1 — rustls TLS 1.3
- Pin `rustls >= 0.23.46` (latest 0.23.46, Oct 2025): 0.23.45/46 fix TLS 1.3 handshake-level bugs (GHSA-2mjx-qc3c-rqvc; ServerHello poisoning of X25519MLKEM hints; Brotli cert decompression). [rustls releases](https://github.com/rustls/rustls/releases) · [crates.io](https://crates.io/crates/rustls)
- TLS 1.3 always available; `tls12` feature is on by default — set `default-features = false, features = ["ring"]` (or `aws_lc_rs`) for TLS 1.3-only. 0.24 will require explicit provider; 0.23 lets `install_default()`. From 0.24 provider split into `rustls-ring`/`rustls-aws-lc-rs`. [rustls docs](https://rustls.dev/docs) · [crates.io](https://crates.io/crates/rustls)
- Trust: use `rustls-platform-verifier` 0.7.x (uses Android platform verifier, CRL/revocation support since 0.2.0 of the Android component; `rustls-platform-verifier-android` crate synchronizes Cargo↔Gradle AAR version). Must initialize Android verifier from JNI before first verify or it panics. [PV releases](https://github.com/rustls/rustls-platform-verifier/releases) · [PV-android docs](https://docs.rs/rustls-platform-verifier-android) · [reqwest #2025](https://github.com/seanmonstar/reqwest/issues/2025)
- aws-lc-rs does not require cmake on common platforms; ring is easier cross-platform but lacks PQ. For arm64 tablet either works; prefer `ring` for smaller cross-build surface unless PQ required. [rustls docs](https://rustls.dev/docs)

### P1 — AAudio via NDK, directly from Rust (no C shim needed)
- AAudio is a stable public C API since API 26; `#include <aaudio/AAudio.h>`; builder pattern, low latency. Available on API 33/36. [NDK guide](https://developer.android.com/ndk/guides/audio/aaudio/aaudio)
- Rust options: `ndk` 0.9.0 with feature `audio` gives safe-ish `AudioStreamBuilder`/`AudioStream` incl. `data_callback` [docs.rs/ndk/audio](https://docs.rs/ndk/latest/ndk/audio/index.html); raw `aaudio-sys` [docs.rs](https://docs.rs/aaudio_sys/latest/aaudio_sys/) or `raw-ndk-sys` (bindgen, zero-overhead, NDK 27.3 headers) [docs.rs](https://docs.rs/raw-ndk-sys/latest/raw_ndk_sys/); or `cpal` 0.18.2 (AAudio backend, MSRV 1.85, needs `ndk_context::initialize_android_context(vm, activity)` from `JNI_OnLoad`). [cpal](https://github.com/RustAudio/cpal)
- Callback rules (glitch avoidance): no malloc, file/network I/O, mutex, sleep; use data callback + lock-free ring; `LOW_LATENCY` performance mode, try `EXCLUSIVE` sharing (lower latency, can disconnect), buffer ≈ 2 × `framesPerBurst`, 48 kHz to avoid SRC. [low-latency guide](https://developer.android.com/games/sdk/oboe/low-latency-audio)
- Thread safety: don't call `waitForStateChange`, or read/write the same stream, from two threads; don't close while reading; `AudioStream` is not `Send`/`Sync` in ndk 0.9.0 (cpal wraps in `Arc<Mutex>`). [NDK guide](https://developer.android.com/ndk/guides/audio/aaudio/aaudio) · [cpal source](https://raw.githubusercontent.com/RustAudio/cpal/v0.18.2/src/host/aaudio/mod.rs)
- Google recommends Oboe C++ wrapper for device quirks, but blueprint keeps C only for PRoot — use `ndk::audio` from Rust and isolate device quirks behind a versioned adapter; consider Oboe only if the Redmi Pad's AAudio path misbehaves.

### P2 — GitHub Actions caching for Rust Android builds
- Use `Swatinem/rust-cache@v2`: caches `~/.cargo` (registry, git deps) and `./target` **dependencies only**, prunes workspace crates/incremental/older-than-week before saving, sets `CARGO_INCREMENTAL=0`; key includes rustc version, all `Cargo.lock`/`Cargo.toml` hashes, toolchain files, `RUSTFLAGS`. Use `shared-key`, `save-if: ${{ github.ref == 'refs/heads/main' }}`, `cache-on-failure`. Repo cache cap 10 GB, evicts oldest. [rust-cache](https://github.com/swatinem/rust-cache) · [Dagger](https://dagger.io/learn/cache-rust-builds-in-ci/) · [compiler.dev](https://compiler.dev/guides/cache-cargo-github-actions)
- Pin `rust-toolchain.toml` + **one** NDK version string; install cargo-ndk via `cargo-binstall` (not `cargo install`) to save CI minutes. [davthecoder CI](https://www.davthecoder.com/blog/ci-cd-rust-android-github-actions)
- Separate caches per target triple / profile: host `rust-host-` vs Android `rust-android-`, and per-ABI keys; four release ABIs fill the 10 GB quota and stale artifacts count against it. [davthecoder CI](https://www.davthecoder.com/blog/ci-cd-rust-android-github-actions) · [RustTraining](https://microsoft.github.io/RustTraining/engineering-book/ch11-putting-it-all-together-a-production-cic.html)
- Optional second layer: `mozilla-actions/sccache-action` with `SCCACHE_GHA_ENABLED: "true"` + `RUSTC_WRAPPER: sccache` (caches individual rustc outputs); composes with rust-cache. [ethanhann](https://ethanhann.com/blog/faster-rust-ci) · [compiler.dev speed](https://compiler.dev/guides/speed-up-rust-cargo-github-actions)
- Fastest signal: `cargo test --locked` on host (no NDK/emulator); emulator job only for the JNI border, x86_64 single ABI, hardware KVM. Use `taiki-e/install-action` for tools, `cargo nextest`. [davthecoder CI](https://www.davthecoder.com/blog/ci-cd-rust-android-github-actions)
- Watch out: `CARGO_ENCODED_RUSTFLAGS` doesn't affect build scripts/proc-macros, unlike `RUSTFLAGS`; keep flags identical across jobs sharing a cache. [RustTraining](https://microsoft.github.io/RustTraining/engineering-book/ch11-putting-it-all-together-a-production-cic.html)

## Deliverable — recommended minimal dependency set for Dextop M5

**Tooling / pins (not runtime deps)**
- `rust-toolchain.toml`: stable **>= 1.86** (cargo-ndk v4 MSRV; cpal AAudio MSRV 1.85; rustls MSRV 1.71) — pin exact channel.
- `androidNdkVersion = "28.x"` in AGP (16 KB default), AGP >= 8.5.1, `compileSdk 36`, `minSdk 33`, `abiFilters += "arm64-v8a"` (+ `x86_64` for tests only).
- Rust targets: `aarch64-linux-android`, `x86_64-linux-android`; `cargo binstall cargo-ndk@4.1.2`; build: `cargo ndk -p 33 -t arm64-v8a -o app/src/main/jniLibs build --release`.

**Crates for `libdextop_core` (`crate-type = ["cdylib"]`)**

| Purpose | Crate / version | Notes / citation |
|---|---|---|
| Control plane bindings | `uniffi = "0.32"` (features `cli` for bindgen bin), proc-macro mode, `setup_scaffolding!()` | No UDL; library-mode Kotlin generation. [davthecoder](https://www.davthecoder.com/blog/uniffi-android-kotlin-bindings-for-rust) · [muhittincamdali](https://muhittincamdali.com/en/blog/rust-mobil-paylasimli-cekirdek-uniffi) |
| Data plane / SPSC ring bridge | `jni = "0.21"` — hand-written exports + `DirectByteBuffer`, all `unsafe` isolated | ~3 ns primitive overhead, zero-copy buffer path. [AOSP](https://source.android.com/docs/setup/build/rust/building-rust-modules/android-rust-patterns) · [JNI ByteBuffers](https://www.davthecoder.com/blog/passing-data-kotlin-rust-jni-bytebuffers-zero-copy) |
| AAudio | `ndk = { version = "0.9", features = ["audio", "api-level-33"] }` | Direct Rust AAudio; no C shim. [docs.rs](https://docs.rs/ndk/latest/ndk/audio/index.html) |
| TLS 1.3 | `rustls = { version = ">=0.23.46", default-features = false, features = ["ring"] }` | TLS1.3-only (no `tls12`); `ring` provider chosen for cross-build simplicity. [rustls docs](https://rustls.dev/docs) · [releases](https://github.com/rustls/rustls/releases) |
| Android trust store | `rustls-platform-verifier = "0.7"` + Gradle AAR `rustls-platform-verifier-android` (0.2.x) | Revocation/CRL support; initialize from JNI. [PV releases](https://github.com/rustls/rustls-platform-verifier/releases) |
| JNI context bootstrap | `ndk-context` (only if any NDK/AAudio API needs `JavaVM`/Activity) | Needed by cpal; call `initialize_android_context` in `JNI_OnLoad`. [cpal](https://github.com/RustAudio/cpal) |

**Deliberately excluded from M5 minimum:** `tokio` (use std threads + the SPSC ring; add only if async I/O proves necessary), `anyhow`/`thiserror` (UniFFI already maps typed errors), third-party ring-buffer crates (hand-roll the 64 KB SPSC to keep the hot path auditable), `cpal`/Oboe (keep only if `ndk::audio` fails on device), BoltFFI (too new).

**CI skeleton (GitHub Actions only, per BRIEF):** `actions/checkout` → `dtolnay/rust-toolchain@stable` (or pinned file) → `Swatinem/rust-cache@v2` (`shared-key: android`, `save-if: main`, separate key per ABI/target) → `cargo binstall cargo-ndk` → `cargo test --locked` (host) → `cargo ndk -p 33 -t arm64-v8a -o jniLibs build --release` → `check_elf_alignment.sh` + `zipalign -c -P 16` gate → emulator JNI test (x86_64, KVM). [rust-cache](https://github.com/swatinem/rust-cache) · [davthecoder CI](https://www.davthecoder.com/blog/ci-cd-rust-android-github-actions) · [xckevin](https://xckevin.com/en/blog/android-16kb-page-size-elf-ndk)

## Risks / device testing needed
1. **16 KB page size**: confirm whether HyperOS 3 on this Redmi Pad Pro actually boots 16 KB pages (developer option) and run `check_elf_alignment.sh`/`zipalign -c -P 16` on the release AAB. Wrong NDK or stale prebuilt `.so` (incl. PRoot C libs) will fail at install/runtime.
2. **UniFFI overhead**: benchmark per-call cost on-device (JNA ~1.5 KB/3.5–4 µs, worse off-JVM-thread) before finalizing control-plane API granularity; reverify if UniFFI ships the per-thread `RustCallStatus` fix from #3056.
3. **JNI ring**: validate DirectByteBuffer lifetime/GC pinning and that no JNI calls occur while holding `GetPrimitiveArrayCritical` regions; confirm no panics unwind across JNI.
4. **AAudio on HyperOS**: EXCLUSIVE streams may disconnect or be denied; test callback glitch-free operation at 120 Hz display load, buffer = 2 × burst, 48 kHz; add a versioned adapter/fallback to SHARED mode or Oboe if vendor quirks appear.
5. **rustls-platform-verifier**: Android verifier must be initialized before first handshake; test CRL/revocation paths and captive-portal/enterprise Wi-Fi trust on-device.
6. **CI cache**: 10 GB limit with 4 ABIs — monitor cache size, use per-target keys and `save-if: main` to avoid evicting useful entries; verify pinned rustc/NDK versions actually match local toolchain file.
