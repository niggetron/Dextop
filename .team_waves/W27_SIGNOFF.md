## Top 3 residual risks — Redmi Pad Pro 5G (Android 16 / API 36 / HyperOS 3)

1. **P0 — Zero on-device validation; scoped tablet identity is an unverified 4-way AND.** `DeviceProfiles.kt:69-87` ANDs manufacturer + `device=duchamp` + `fingerprintPrefixes` {redmi/duchamp, xiaomi/duchamp} + minSdk 36. Any mismatch silently falls to broad `xiaomi_hyperos` → loses `pinMetrics`, `maxRateApplicationDisplays`, `pinPhysicalMouseToDesktop`, `directDeckKeyboardToApp` — i.e. portrait/shrunken desktop. `CapabilitySnapshot.toReportLines()` omits `product`/`fingerprint`, so a broad match is hard to diagnose. M1 capture tool exists but has never been run; no `duchamp` capture in tree. **Must do:** run `tool/hyperos_capability_capture.sh` on the tablet; confirm snapshot `device: duchamp`, `matchedRuleId: xiaomi_redmi_pad_pro_5g`, `recommendedBackend: E`. A broad match invalidates every tablet result.

2. **P0 — Hidden-API fragility on HyperOS 3; effective 120 Hz and escape hatches are off/unreachable.** Forced metric pinning via `wm size/density -d` + `HiddenApiBypass 6.1` + Shizuku + direct VirtualDisplay is gated on the scoped rule and flags (`MirrorService.kt:12208,12516,12712,13387`); rejection reverts to the phone-size portrait desktop/pointer strip. 120 Hz app windows are behind `experimental_maximum_mirror_refresh_rate` default **false** (`CompositedWindowShell.kt:1276`, `DisplayEnvironmentSettings.kt:25`) — expect 60 Hz on the 12.1" panel. `xiaomi_tablet_touch_mode` and `xiaomi_topology_layout` are documented in README but have **zero readers** (dead); all five `xiaomi_*` kill switches are unreachable from any release UI (no method-channel/Dart writer). If HyperOS breaks a hidden call, the user has no in-app fix. **Must verify:** `dumpsys display | grep -i refresh`, OperationLog `XiaomiMetrics = applied/rejected`, and the snapshot's `supportsInternal120Hz`/`forceInternal120Hz`.

3. **P0 — Crash recovery and install path unproven; graphics gain likely zero on this device.** `kill -9` atomic-WAL restore and the detached 15 s watchdog rollback (`WatchdogClient/Daemon/Protocol`) have only JVM framing tests, never a device run. Builds are debug-signed with a per-build suffix `moe.n4tsu.dextop.r<hash>` → side-by-side install, no settings carry-over, no upgrade path; beta.4 versionCode skew was fixed in code (`c95c824`) but not re-verified on-device, and the CI gate's zizmor/`$/` reusable-call fixes are untested in Actions. Separately, the only shipped zero-copy path (`deck_ahb_broker.inc`, BUG-05) is **Steam-only** — the Redmi Pad Pro 5G is not Steam, so even the graphics hardening yields no compositing win here. **Must test:** WAL restore after `kill -9`, 15 s rollback, upgrade order beta→stable→beta, and side-by-side package co-install.

Brutal bottom line: **M0–M2 are code-complete but unproven; M3–M8 are paper. Nothing here is validated on the user's tablet.** Do not represent this tree as a shipped desktop replacement — ship the debug APK, capture diagnostics, and treat the device run as the first real test.
