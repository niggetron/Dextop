## Findings
- **P1 — resources carry only 19 of ~1938 display strings** (`generate_native_strings.py:42-62,125-127`; `generate_inline_strings.py:50-64`). Native Compose/Views bypass `Resources`: no per-app language prefs (Android 13+/API 36), no resource qualifiers, no `stringResource()` in Compose, and manual locale maps break on the device's full locale list. Fix: emit **all** native + android + ui keys as `values*/strings.xml` in each consuming module; keep `.properties` only as a transition shim.
- **P1 — wrong fallback locale**: app default `values/` is Japanese (`generate_native_strings.py:33-41,139`) but `NativeStrings.kt:10-12` falls back to English. Unsupported locales would regress to Japanese after migration. Fix: make `en` the default (`values/`) and move `ja→values-ja` (match `cardex` and Android convention); pt-BR stays `values-pt-rBR`.
- **P1 — placeholder/escaping dialect mismatch**: inline `{0}`→`%1$s`, `{1}`→`%2$s`, `{2}`→`%3$s`; literal `%`→`%%`; `'`→`\'`, `@`→`\@`, `?`→`\?`, `"`→`\"`, `\`→`\\`, literal `\n`→XML `\n`. 6 EN inline texts have `%`, 34 have apostrophes; 14 native texts already use `%N$d/%N$.1f/%02d` (copy verbatim) and `nativePerformanceHudFormat` reorders `%6$s` before `%5$s` (legal). Without this aapt2 fails or text renders wrong on API 36/HyperOS.
- **P2 — formatted call sites**: `NativeStrings.text(k).format(args)` and `InlineStrings.format(localText(k), args)` must become `getString(R.string.<k>, args...)` / `stringResource(R.string.<k>, args...)`; `getString` applies `String.format` to the resource, so argument order must match `%1$,%2$…`.
- **P2 — CI coupling**: localization check gated behind Flutter job (`.github/workflows/pr-checks.yml:50,76-77`); after Flutter retirement the parity check must run standalone with Python only.
- **P3 — existing resource check is key-only** (`check_localization.py:129-146`): verifies names, not format specifiers or escaping. Extend to canonical placeholder signatures.
- **P3 — `check_apk_localization.py`** validates packaged `.properties`; retire with the shim, or extend to unpack `resources.arsc` string counts if APK verification is retained.

## Deliverable — exact migration design

### 1. Canonical key map (single source, generated)
Resource name = catalog key verbatim (all keys match `[A-Za-z][A-Za-z0-9_]*`), except the existing 19 aliases. Extend `ANDROID_KEYS` in `generate_native_strings.py:42-62` to the authoritative alias table; reserve `app_name` + `quick_settings_tile_label` (`translatable="false"`). Resource dirs: `en→values` (default), `ja→values-ja`, `zh→values-zh`, `ko→values-ko`, `ru→values-ru`, `pt→values-pt`, `pt_BR→values-pt-rBR`.

### 2. Generator changes
- **`generate_native_strings.py`** → keep name, drop `NativeStrings.kt` emission; emit app `values*/strings.xml` for all `native*` (288) + `android*` (17) + aliases, per locale from ARB. Add `android_text(text)`:
  - `text.replace("\\n", "\n")` (literal backslash-n) and real newlines → XML escape `\n`;
  - escape `\`, `"`, `'`, `@`, `?` (leading), `&`, `<`, `>`; keep valid `%N$…` specifiers intact, convert stray `%`→`%%`;
  - emit `<string name="…">…</string>` with `formatted="true"` only for the 14 format keys, else `formatted="false"` (prevents aapt from treating stray `%` as format).
- **`generate_inline_strings.py`** → add app `values*/strings.xml` outputs for all 1630 `ui*` keys with `{n}`→`%n+1$s`, literal `%`→`%%`, then same escaping; `formatted="true"` for the 170 template keys. Keep cardex `companion_resource_keys.json` subset unchanged (with its quoted/`formatted="false"` form). Keep Dart + `.properties` outputs behind a `--legacy` flag during M3; default outputs become resources only. `--check` compares all generated files.
- **Transitional Kotlin shim** (generated, then deleted): replace `NativeStrings.kt`/`InlineStrings.kt` bodies with `getString(key, varargs)` over a generated `mapOf(key to R.string.key)` and `AppStrings.context` from `DextopApplication`; `NativeStrings.text`, `localText`, `InlineStrings.format` delegate to it so the 913 call sites can be rewritten mechanically. Final state: `stringResource(R.string.key)` in Compose, `context.getString(R.string.key, args)` elsewhere; `t()/tr()/trf()` wrappers removed.
- **Manifest/XML sinks**: existing `@string/quick_settings_display_tile_label`, `@string/dextop_swipe_ime_label`, `@string/accessibility_service_description`, `@string/embedded_pairing_*`, `@string/dextop_shortcut_*` names stay identical — no XML edits needed.

### 3. CI parity check replacing `check_localization.py`
New `tool/check_string_resources.py` (Python stdlib only; no Flutter/Gradle):
1. Parse every `android/{app,cardex}/src/main/res/values*/strings.xml` with `ElementTree`; reject duplicate names; compare name sets to the reference locale (app=en default, cardex=en default) excluding `translatable="false"`; assert every non-default dir exists for all 7 locales.
2. Compute canonical signature per value: `%(\d+\$)?[-+#0 ]*\d*(\.\d+)?[a-zA-Z]` → tuple `(position or implicit-order, conversion)`; `%%` ignored; for source catalogs expand inline `{n}`→`(n+1,'s')` and use native `%N$` as-is. Assert resource signature == source signature == signature in every locale; assert no empty translations.
3. Assert generator idempotence via `generate_native_strings.py --check` and `generate_inline_strings.py --check` (resource mode).
4. Static sweep (reuse `inline_strings.py`/`localization_literals.py`): no hardcoded prose in display sinks; after cutover, no `NativeStrings.text`/`localText`/`InlineStrings.format` calls; every `R.string.X` referenced in Kotlin exists in the resource set.
5. Workflow: add `strings` job in `pr-checks.yml` (timeout 5 min, Python 3 only), triggered by `^(lib/l10n/|tool/(generate_|check_).*\.py$|android/.*/res/values|android/.*/src/main/kotlin/|\.github/workflows/pr-checks\.yml$)`; remove `Check UI localization` step from the Flutter job and remove `check_localization.py` after cutover. `result.needs` gains `strings`. Keep `check_apk_localization.py` only while `.properties` ship.

### 4. Verification steps (no local builds)
- `python3 tool/check_string_resources.py` → key + placeholder parity across 7 locales × 2 modules.
- `python3 tool/generate_native_strings.py --check && python3 tool/generate_inline_strings.py --check` → generated resources current.
- `git diff --check`; confirm `values/strings.xml` count ≈ 1935 names/locale (288 native + 17 android + 2 aliases + 1630 ui, minus module subset).
- GitHub Actions `Debug APK` (not local) → aapt2 validates escaping/format strings; `check_apk_localization.py` (transition) confirms packaged catalogs.
- Device smoke on Redmi Pad Pro 5G / HyperOS 3 / API 36: switch system locale to ja/en/zh/ko/ru/pt-BR; verify tile label, swipe IME label, pairing notification, shortcuts, Performance HUD (`%1$.1f`, out-of-order `%6$s`), Plasma "Desktop %1$d"/countdowns; enable per-app language override and confirm resources follow it.

## Risks / device testing needed
- Locale fallback change (ja default → en default) must be accepted in M3 sign-off; verify ja device still gets Japanese via `values-ja`.
- Two dialects (`%N$` native vs `{N}` inline) and 1-based vs 0-based indices are the main regression source; CI check is mandatory, not optional.
- Escaping apostrophes/`%` incorrectly is invisible in Python checks unless rule 2 and aapt2 both run; do not skip the Debug APK workflow.
- 913 call sites rewritten; shim keeps behavior stable during transition but deletes only after full sweep passes.
- `{0}` templates passed non-String args (Int) still work with `%N$s`; verify no `%N$d` was introduced by conversion.
